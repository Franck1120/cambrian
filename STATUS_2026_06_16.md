## 4. Fix harness portato in questa sessione (lezione reale)

Il vecchio harness aveva un **bug di onestà**: quando una call esauriva la quota
(429), `make_evaluator` catturava l'eccezione e ritornava `0.0` **silenziosamente**.
Risultato: una run a quota esaurita sembrava "tutti i metodi falliscono" — un verdetto
falso e dannoso (lo stesso peccato che stiamo estirpando da Cambrian).

**Ora l'harness aborta rumorosamente:**
- `_CountingBackend` classifica gli errori 429/quota/auth come `BackendExhausted`.
- `_preflight()` fa 1 call di prova: se la key è morta dall'inizio → exit 2 con istruzioni.
- Esaurimento a metà run → scrive `humaneval_<date>_ABORTED.json` con `status:
  ABORTED_BACKEND_EXHAUSTED` invece di un verdetto. **Mai più zeri spacciati per risultato.**
- Verificato con backend fittizio: preflight aborta (exit 2), evaluator propaga
  l'eccezione, classificazione corretta. Mock end-to-end invariato.
